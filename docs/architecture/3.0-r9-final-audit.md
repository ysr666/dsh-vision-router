```text

        |
        v
```

## R9 findings and repairs

R9 was not a ceremonial re-run. It found several integration defects that ordinary
unit/CI coverage did not expose and repaired them before closure.

### 1. Frozen Host Dispatcher Proxy invariant

The typed provider transport correctly moved DVR toward the public Undici Dispatcher
contract, but the per-hop wrapper originally used the borrowed Host dispatcher itself as
a JavaScript Proxy target.

A Host dispatcher may expose `dispatch` as a frozen/non-configurable own property. A
Proxy `get` trap that substitutes another dispatch function then violates ECMAScript
Proxy invariants and throws before network dispatch.

R9 changed the wrapper to use a neutral shell with the same prototype while forwarding
all non-dispatch reads/method calls to the borrowed fallback dispatcher.

Result:

- DVR still does not own or close the borrowed fallback;
- full Dispatcher method/event surface remains available;
- prototype/instance-style compatibility is preserved;
- the wrapper can safely override only the dispatch routing seam.

The transport regression suite passes after the repair.

### 2. Cross-repository Host workflows still assumed tracked artifacts

R1 removed `entry.js`, `index.js` and `lib/**` from Git. Several real-Host and exact
source workflows still checked DVR out under `dvr/` and immediately handed that checkout
to DSH as if generated package artifacts were tracked.

This caused exact-source failures such as:

```text
Cannot find .../dvr/lib/dsh-contract-compat.js
```

and real Host/browser failures where the package topology was incomplete.

R9 updated every current cross-repository DVR checkout workflow to materialize the
package explicitly:

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm build:check
```

before DSH consumes the package.

A permanent architecture gate now requires one explicit materialization step per current
`path: dvr` checkout job.

### 3. Peer-admission gate had a stale hard-coded DSH peer list

The Host admission evaluator assumed DVR declared only two DSH peers. 3.0 legitimately
uses the public `@deepseek-ai/dsh-storage-domain` type contract for the optional durable
Session policy sidecar, so the hard-coded peer list drifted from the package manifest.

R9 changed admission verification to derive the complete DSH peer set from
`package.json` rather than silently maintaining a second list.

This does not broaden admission. The same compatibility expression is still evaluated for
every declared DSH peer.

### 4. Optional Cordis capabilities were read as direct service properties

Real DSH Host/Desktop runs exposed an important Cordis lifecycle rule that ordinary object
fixtures did not model: directly reading an undeclared optional service property can turn
capability detection into a hard pending dependency.

R9 repaired three seams:

- Session projection lookup now uses `Context#get('sessionProjections')`;
- optional storage-domain lookup now uses `Context#get('storageDomain')`;
- Agent delegation binding now enters through
  `ctx.inject(['agents'], agentsCtx => ...)`.

Regression fixtures now deliberately throw on direct optional service-property reads so a
future refactor cannot accidentally recreate the hard dependency.

This preserves the intended ownership model:

```text
optional capability
  -> capability-safe Host lookup / explicit lifecycle child
  -> narrow DVR boundary
```

instead of:

```text
optional capability
  -> implicit Cordis dependency
  -> plugin remains pending
```

## Negative architecture audit

R9 explicitly rechecked the 3.0 non-goals.

Production source contains no introduced:

- `DvrContext`;
- giant `HostFacade`;
- generic service locator / DI container;
- global current owner / registry;
- `Object.create(core)` facade;
- private DSH `/src/` production import;
- `@ts-ignore` or `@ts-nocheck` suppression.

`runtime-composition.js` remains a composition root rather than becoming a second Core.

R9 did not:

- convert mature Core merely for TypeScript percentage;
- raise the browser size gate;
- introduce a browser bundler/minifier as an architecture fix;
- delete runtime validation;
- collapse Host and Client compiler worlds;
- narrow historical durable-data compatibility;
- raise the DSH Host floor without evidence.

## Final 3.0 architecture verdict

The architecture work described by the 3.0 plan is complete.

3.0 now has:

- one canonical source tree;
- explicit generated package artifacts;
- strict, separate Host and Client compiler worlds;
- typed high-value lifecycle/domain owners;
- runtime validation at dynamic boundaries;
- explicit provider/resource/Session ownership;
- an intentionally narrow package-root runtime/type API;
- evidence-based compatibility retention/retirement;
- a deliberate Browser TypeScript No-Go rather than a weakened size/build contract;
- release and packed-package gates aligned with canonical source ownership;
- real Host/Desktop evidence across the supported DSH window.

The next work should therefore be release preparation or bug-driven follow-up, not another
architecture migration pass.

No PR, merge to `main`, 3.0 version bump, tag or formal 3.0 release is performed by
this R9 closure.
