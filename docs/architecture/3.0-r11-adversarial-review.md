# R11 — Adversarial final audit (3.0)

Status: in progress. This document is the working record for R11. It is **not** a
release declaration: no version bump, tag, publish or GitHub Release is part of
R11, and nothing here claims 3.0 is release-ready.

Baseline for R11: `05e7483` (`docs(3.0): mark R10 integrated`), branch
`r11-adversarial-final-audit`.

## 1. Why every review round keeps finding more defects

The defects found across R0–R11 are not randomly distributed. They cluster into a
small number of structural classes, and each class lives at a boundary that
ordinary behaviour tests do not exercise:

| Class | Shape of the defect | R0–R11 examples |
| --- | --- | --- |
| A. Dynamic Host boundary read as a typed value | A `ctx.*` seam is typed/generic, but the Host may hand a partial, null, throwing or replaced value at runtime | `tools.register(null)`, `attachments` access, credential/attachment runtime guards | 
| B. Async lifecycle ownership | A resource is created before its disposer is registered, or the disposer does not await retirement | `storageDomain.open()` before `ctx.effect(close)`, `void dispose()`, async teardown with no observer |
| C. HMR generation leak | Generation-scoped state (WeakMap caches, timers, listeners, in-flight work) outlives its generation and is reused by the next one | stale wrapper WeakMaps, background benchmark ticks, Ollama warmup, file logger sink |
| D. Unordered async completion | State that is written by several async paths has no ordering or admission rule | Session Vision policy `set A` / `set B`, hydrate vs set vs delete |
| E. Optional capability materialised as a dependency | An optional service is read through the dependency-enforcing property path | `ctx.attachments`, `ctx.sessionQuery`, `ctx.sessionProjections`, `ctx.systemPrompt` |
| F. Global/process state without an owner | A process-wide seam is read or wrapped per call instead of with an explicit owner and restoration | `globalThis.fetch` capture (R10), dispatcher pool, `Symbol.for` registries, `process.env` |
| G. Public contract vs runtime drift | `.d.ts` / docs / the packed sample describe something the runtime does not do | `apply(ctx, config, runtime?)`, `installHostSettingsCompatibility`, `sessionSurfaceReplacementIntent` |
| H. Build/client/release topology drift | The artifact/release state machine does not match what the code assumes | generated-artifact triggers, tag-before-pack, provider transport typing |

Two second-order causes make this recursive:

1. **A fix can create the next defect.** The R10 provider-transport bug was
   introduced by the TypeScript migration itself: `globalThis.fetch.bind(globalThis)`
   became `(input, init) => globalThis.fetch(input, init)`, which is semantically
   different. R11 found the mirror image: wrapping a Host contract call inside a
   Cordis `effect()` factory changes *when* it runs, and a Host that does not
   eagerly execute the factory never subscribes to live Settings at all.
2. **"Verified" was defined as "tests are green".** Coverage went up while the
   discovery process stayed manual, so each review pass inspected a different
   dimension and the total never converged. The stopping rule has to be
   structural, not "we ran out of ideas".

## 2. Stopping rule for R11

R11 is complete when all of the following hold, not when the suite is green:

1. Every effect/registration/disposer/timer/listener/global-mutation site in
   `src/**` has been read and classified against the checklist in §3.
2. Every dynamic Host boundary has an adversarial test that feeds
   `null`/`undefined`/primitive/throwing/partial/late/replaced values.
3. Every async teardown returns an awaitable retirement and its failure path is
   either propagated or explicitly documented.
4. The release state machine can reach every state from every partial state, or
   refuses deterministically with a clear operator instruction.
5. The mechanical invariants in §4 are enforced in CI, so a fixed regression
   cannot silently return.
6. The real DSH Desktop matrix in §6 has been executed by hand and recorded here.

### 2.1 Triage rule that makes the stopping rule reachable

"It keeps finding defects every round" is itself a finding: it means the
verification loop had no structural closure. So every defect found from here on
is triaged, not just fixed:

1. Assign it to one of the classes in §1 → fix it, then ask whether that class
   now has a gate (lint rule, adversarial test, negative contract test). If not,
   add one in the same change.
2. If it fits no class → the taxonomy has a hole: extend §1 and this stopping
   rule **first**, then fix the instance. Fixing only the instance guarantees the
   class returns in a new shape next round.
3. "Look at it more carefully" is not a convergence mechanism. The list above is.

## 3. Review checklist (per site)

For every resource or seam, answer explicitly:

- Who creates it?
- Who owns it (which generation / fiber)?
- Who retires it, and is the retirement awaited?
- What happens to a late completion after unload?
- Can an old generation write new-generation state?
- Is the read path a declared dependency, an optional probe, or an owned mutation?
- Is the input trusted because a type says so, or validated because it crosses a boundary?
- Does a failure here leave the Host in a half-installed state?

## 4. Mechanically enforced invariants

`scripts/lint-lifecycle-invariants.mjs` (wired into `pnpm lint`, see
`tests/lifecycle-invariants.test.js`):

- **L1 sealed-process-global** — a process-wide global (today `globalThis.fetch`)
  read at call time instead of captured once at module load.
- **L2 optional-capability-direct-read** — a bare `ctx.<optionalCapability>` read
  outside a declared dependency or a guarded probe.

Both rules are proven on the shipped tree and on positive/negative fixtures. The
remaining classes are checked by reading, because deciding them needs the owning
module's semantics.
