# DVR 3.0 R8 — CI / release closure

Status: **complete**

R8 aligns the 3.0 canonical-source build with CI, packing and the existing trusted
release model. It does not replace the 2.3 pack-once / tarball-identity / OIDC /
provenance design; it closes the new source/type/declaration gaps around that design.

## Release blocker found during R8

R1 intentionally removed generated runtime artifacts from Git:

```text
src/**
  -> build
entry.js
index.js
lib/**
```

and added:

```text
prepare = pnpm build
prepack = pnpm build
```

The pre-3.0 release workflow still had two incompatible assumptions:

1. release verification rejected `prepare` and `prepack` as forbidden lifecycle
   scripts;
2. the publish phase set `NPM_CONFIG_IGNORE_SCRIPTS=true`, checked out a clean tree,
   did not install/build package artifacts, then executed `npm pack`.

Because generated JavaScript is no longer tracked, that publish path could have packed a
tarball without the canonical runtime artifacts.

R8 fixes the release path instead of weakening R1.

## Canonical source ownership lint

R8 adds:

```text
pnpm lint
  -> scripts/lint-source-ownership.mjs
```

The gate verifies:

- every canonical non-declaration `.ts` owner is present in `tsconfig.build.json`;
- every canonical Host `.ts` owner is present in `tsconfig.host.json`;
- stale TypeScript build includes fail closed;
- two canonical source files cannot claim the same package artifact;
- production source cannot contain `@ts-ignore` or `@ts-nocheck`;
- production source cannot import DSH private `/src/` entry points;
- `entry.js`, `index.js` and `lib/**` cannot return to Git source-of-truth.

At closure the gate reports:

```text
38 typed runtime owners
182 canonical package artifacts
```

## Source-to-artifact evidence

R8 adds:

```text
pnpm source:artifact:check
  -> scripts/verify-source-artifact-map.mjs
```

It proves one package artifact for every canonical JS/TS/declaration source and rejects:

- missing generated artifacts;
- orphan generated artifacts;
- canonical ownership collisions;
- copied JS/declaration byte drift.

For compiled TypeScript it records the canonical-source and emitted-artifact hashes rather
than pretending compilation is byte identity.

## Packed public API smoke

R8 adds:

```text
scripts/verify-packed-public-api.mjs <existing-package.tgz>
```

The script never repacks. It validates the exact candidate supplied by its caller:

- package `main`, `types`, root conditional exports and `./client`;
- required runtime/declaration artifacts;
- canonical `src/` is not shipped;
- exact twelve R7 runtime exports;
- a strict NodeNext TypeScript consumer resolves the packed declaration;
- an accidental mature-Core helper such as `createCache` is not package-root API.

This gives declarations a packed-package contract rather than validating only the
repository checkout.

## CI

The Node 22 CI path now runs:

```text
frozen install
build
build:check
build:reproducible
Host + Client typecheck
source ownership lint
source-to-artifact evidence
client generated-source check
full runtime suite
```

A separate `packed public API` job:

1. performs the canonical build;
2. packs one candidate;
3. runs the packed runtime/declaration smoke against that tarball.

Node 24 continues to run the full runtime suite, while Linux/macOS/Windows native Host
jobs retain their sharp/package installation checks.

## Release verification phase

Release verification now explicitly validates the 3.0 source contract:

```text
install locked dependencies
build
build:check
lint
source:artifact:check
build:reproducible
typecheck
full tests
client:check
Host support-window contract
```

The lifecycle security check permits only the two required build hooks and pins their
contents exactly:

```text
prepare = pnpm build
prepack = pnpm build
```

Install/publish lifecycle hooks with unrelated execution authority remain forbidden.

## Trusted publish phase

The publish phase deliberately keeps:

```text
NPM_CONFIG_IGNORE_SCRIPTS=true
```

It now performs:

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm build:check
pnpm lint
pnpm source:artifact:check
npm pack --json        # exactly once
verify-packed-public-api <that exact tarball>
registry identity / publish / provenance
```

So a release no longer depends on npm lifecycle scripts to materialize package code.

The pre-existing supply-chain design is unchanged after the tarball is created:

- one exact tarball is hashed;
- the same tarball is probed/published;
- trusted OIDC publishing remains enabled;
- registry SHA identity is verified;
- SLSA/GitHub provenance binds the exact tarball;
- GitHub Release rehydrates and verifies the same npm artifact.

## Clean publish simulation

R8 reproduced the trusted-publish shape from a clean checkout:

1. `pnpm install --frozen-lockfile --ignore-scripts`;
2. asserted `entry.js`, `index.js` and `lib/` were still absent;
3. explicit canonical build;
4. build/source ownership verification;
5. one `npm pack`;
6. packed runtime/declaration smoke.

Result:

```text

```

The package version remains 2.3.0 because R8 is architecture/release-path validation,
not the 3.0 release/version-bump phase.
