# DVR 3.0 R1 source/artifact boundary

Status: **complete**

R1 was intentionally split so source relocation and artifact removal were not performed
in one unreviewable change.

## Final source/artifact model

The canonical editable runtime tree is `src/`, preserving the established 2.3 package
artifact topology:

```text
src/entry.js / transitional .ts       -> entry.js
src/index.js / transitional .ts       -> index.js
src/lib/**/*.js / src/lib/**/*.ts     -> lib/**/*.js
```

`entry.js`, `index.js`, and `lib/**` are generated package artifacts and are no longer
tracked by Git.

The move did not authorize import rewrites, Core decomposition, public API contraction,
or runtime ownership changes. Source relocation and TypeScript migration remain separate
review dimensions.

## Build ownership

`scripts/build-source-artifacts.mjs` is the only writer for the package runtime tree.

A normal `pnpm build`:

1. removes any stale root `entry.js`, `index.js`, and `lib/**`;
2. copies transitional canonical JavaScript from `src/` byte-for-byte;
3. compiles canonical TypeScript in an isolated temporary output directory;
4. copies compiled JavaScript into the established package artifact paths.

This clean-before-build rule prevents deleted or renamed source modules from surviving as
stale files that could later enter `pnpm pack`.

`pnpm build:check` builds into a temporary directory and compares generated output with
the current package tree without mutating it.

`pnpm build:reproducible` performs two clean builds into independent temporary
directories and compares relative paths, byte sizes, and SHA-256 hashes.

## Install and package lifecycle

Repository installs run `prepare -> pnpm build`, so workflows and direct test commands
that historically consumed `lib/**` receive current artifacts from canonical source.

The one security workflow that intentionally installs with `--ignore-scripts`
(`adversarial-fuzz`) has an explicit build step.

`prepack -> pnpm build` is an independent package safety gate. Packaging therefore does
not rely on generated files being present in the checkout or left over from tests.

Generated runtime paths are ignored by Git:

- `/entry.js`;
- `/index.js`;
- `/lib/`.

The npm `files` allowlist continues to name those artifact paths because they are package
outputs, not repository source.

## Workflow trigger migration

Specialized workflows whose path filters referenced the old root `index.js`,
`entry.js`, or `lib/**` now also follow `src/**`. This prevents removal of tracked
artifacts from silently disabling architecture, Host, browser, resource, compatibility,
or fuzz gates.

## Browser client

The browser client remains a separate workstream. Canonical browser source currently
lives under `src/lib/client.js`; its deterministic embedded maintenance-actions sync is
performed on canonical source before package artifacts are rebuilt.

The existing 262144-byte hard review bound is unchanged.

## R1 verification

R1b was verified from a checkout with **zero tracked generated runtime artifacts**:

- frozen install succeeded;
- prepare rebuilt the runtime tree;
- clean build succeeded;
- generated artifact verification succeeded;
- two-build reproducibility succeeded;
- Host and Client typecheck succeeded;
- full Node 22 and Node 24 test suites succeeded;
- Linux and macOS native Host/sharp smoke succeeded;
- Windows runtime regression succeeded;
- Windows `pnpm pack` succeeded with generated artifacts ignored by Git;
- the packed tarball installed into a DSH-like Host with the shared-sharp invariant intact.

R1 is closed. Further source migration is R2/R3/R4 work and must preserve this build
contract.
