# DVR 3.0 R1 source/artifact boundary

Status: **R1a canonical-source mirror**

R1 is intentionally split so source relocation and artifact removal are not performed in
one unreviewable change.

## R1a - canonical source mirror

The canonical editable runtime tree is now `src/`, preserving the exact 2.3 artifact
topology:

```text
src/entry.js      -> entry.js
src/index.js      -> index.js
src/lib/**        -> lib/**
```

This first step deliberately does not rewrite imports, rename modules, split Core, or
change runtime ownership. Existing generated artifacts remain tracked temporarily so all
current tests, workflows, Doctor fixtures, and package smoke paths continue to resolve
while the source-of-truth transition is proven.

`scripts/build-source-artifacts.mjs` is the only writer from canonical runtime source to
the current artifact topology. `pnpm build:check` performs byte-for-byte verification,
and the default full test lifecycle fails before tests if any artifact is stale.

The browser client is relocated without changing its build semantics. Its generated
maintenance-actions region is now edited in `src/lib/client.js`; `client:sync` then
rebuilds the mirrored artifact. The 256 KiB gate remains unchanged.

## Why R1a keeps generated artifacts tracked

Removing `entry.js`, `index.js`, and `lib/**` from Git in the same commit would force
simultaneous edits across a large number of direct source tests, package-smoke fixtures,
and CI workflows. That would mix relocation with test/build behavior and make failures
harder to attribute.

The tracked artifact copy is therefore temporary and guarded against divergence. It is
not a second source of truth.

## R1b exit

R1b will remove ordinary generated Host artifacts from Git only after:

- every source checkout path that requires runtime files performs a build first;
- package/Doctor/Host fixtures consume built artifacts;
- targeted test commands cannot silently exercise stale generated code;
- clean build recreates the package runtime tree from `src/`;
- two clean builds produce identical relative paths and bytes.

R1 does not authorize TypeScript conversion or public API contraction. Those remain R2
and R7 work respectively.
