## 5. Browser/source modularization verdict

R4 moved current Settings product semantics out of compatibility preludes:

- `remote-settings-risk-client-boundary.js` is the single owner for the remote risk/reminder behavior;
- `local-remote-settings-permission.js` owns the local permission normalization/write behavior;
- `settings-client-loader-lifecycle.js` owns only the supported Host queue-to-live reattachment lifecycle.

The old rc.8-labelled source/API name is gone. The historical in-page marker/sentinel remains only for mixed-generation/HMR idempotency.

The standalone remote-risk Web `tapIndex()` fallback is intentionally retained. Moving it onto the shared Desktop structured carrier was reviewed and rejected because Desktop/live attachment is already handled by the loader lifecycle; installing the fallback there would create duplicate wrapper execution, not improve ownership.

Likewise, `settings-factory-lifecycle.js` and `settings-client-loader-lifecycle.js` remain separate because they re-arm different responsibilities. Combining them would couple unrelated lifecycle concerns.

## 9. Retained debt

R5 closes with explicit debt, not a purity claim:

1. **Mature Core remains large.** Further extraction should wait for a stable owner seam rather than chase LOC.
2. **Composition remains high fan-out.** This is acceptable for a construction root but new installers should continue to be challenged.
3. **The delivered browser bundle remains monolithic and near its review bound.** It has only 472 bytes of headroom under the 256 KiB single-file review limit. Do not raise the bound casually; continue source extraction before adding substantial product logic.
4. **Ten compatibility seams remain intentionally supported.** None currently meets its removal condition.
5. **DSH Web activation overlays remain upstream-blocked.** Exact-source watchers must continue to detect when the upstream gap actually closes.

None of these retained items is an unresolved High or Medium 2.3 architecture finding.
