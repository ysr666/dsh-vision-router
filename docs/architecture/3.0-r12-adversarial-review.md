# DVR 3.0 R12 adversarial review

Scope: the unreleased delta on `main` after `v3.0.0`, with the review pointed at the
changes made in this round — the provider-transport coverage fixes (#633 / #634), the
CI cache scoping (#636), and the release audit that preceded them.

Method: attack the claims, not the code. Every candidate finding is checked for
**reachability** before it is called a defect, and a candidate that fails that check is
recorded as falsified rather than quietly dropped. Severity is stated only where a real
user path exists.

## 2. Candidates that did not survive verification

### 2.1 Ollama cold start bypasses `proxy` / `proxyHosts` — falsified

`installOllamaColdStartGuard` receives only `{ logger }`
(`src/lib/runtime-composition.js:140`), while the very next installer receives
`{ providerTransport }` (`:147`). The guard's own `GET /api/ps` probe and
`POST /api/generate` warmup use the module-captured plain `fetch`, which does not apply
the transport's `proxy` / `proxyHosts` decision. Structurally this looks like a third
leg of the same family.

It is not a defect: both requests sit behind an explicit loopback gate
(`src/lib/ollama-cold-start.js:167` returns `{ ok: false, skipped: true, reason:
'non-loopback' }`), and the existing suite pins that rule ("automatic warmup is
loopback-only and never turns a configured remote URL into a new side effect"). A remote
Ollama that needs a proxy therefore never sees this traffic. The residual case — an
operator who puts `127.0.0.1` into `proxyHosts` — is contrived and, if it matters, is
better handled by the same gate than by threading a transport into warmup traffic.

### 2.2 A fix for one leg silently skipped the others

This is the failure mode behind #623 and #633/#634 rather than a defect of its own. The
sweep above exists because "the mechanism is present" is not evidence that every path
uses it; the table records path-by-path coverage instead.

## 3. Observations (not defects, decisions belong to the maintainer)

### 3.1 The self-update check ignores `proxy` / `proxyHosts`

`src/lib/update-check.js` queries the npm registry and the release API with
`moduleFetch` and has no transport reference. On a network where the configured `proxy`
is the only egress, the update check fails while provider traffic succeeds.

Out of family: this is DVR's own version lookup, not provider traffic, and routing it
through the *provider* proxy may be wrong when the proxy is provider-specific. Left
unchanged deliberately; worth an explicit decision (honor the proxy, or document that
the check needs direct egress).

### 3.2 An injected probe fetch still outranks the transport

`installVisionDiagnosticsRoutes` resolves `fetchImpl` → transport → legacy boundary
fetch → module fetch. Production wiring passes no `fetchImpl`
(`src/index.js`), so probes currently follow the transport; a future caller that injects
one would bypass it silently. The precedence is deliberate (explicit injection wins) and
is now documented inline, but it is a place to re-check if the diagnostics routes gain a
second caller.

## 4. Claims re-audited

- **Release invariants.** The release workflow is `workflow_dispatch` only and refuses a
  tag that differs from `package.json`, a target that is not the current `origin/main`
  HEAD, or a tag that already exists. `main` still declares `3.0.0` while carrying
  unreleased fixes, so an accidental release is impossible without a version bump; no
  tag exists beyond `v3.0.0`.
- **Failing-first evidence.** Each of the five fixes shipped this round
  (#619 / #620 / #623 / #633 / #634) has a test that fails on the pre-fix commit and
  passes on `main`; the two newest were re-run on `main@acaf5fe` in a clean worktree.
- **Battery.** Full `pnpm test` on the fixed tree: 1704 tests, 0 failures; packed public
  API smoke passes; workflow-contract suites pass.
- **CI caches.** The Playwright `.deb` cache leaves the install command untouched (apt
  still verifies against the fetched index, so a stale local `.deb` is re-downloaded);
  the Node runtime cache is kept only where it measured faster end to end (macOS). Both
  fail loudly if a cached artifact is corrupt, and both degrade to a normal download
  after eviction.
- **Corrected over-claim.** The #636 description attributed a whole job delta
  (173 s → 101 s) to the Node cache; the attributable part is the two affected steps
  (36 s → 18 s). The pull-request text was corrected.

## 5. Residual uncertainty (not verified)

- Concurrency in the Windows Desktop Host suite has two green runs (including a rerun)
  but no long-run flake history; timing-sensitive assertions there remain the most
  likely source of future intermittent reds.
- The transport's proxy decision depends on the live config read at request time; the
  sweep verified wiring, not behaviour against a real remote proxy for every leg.
