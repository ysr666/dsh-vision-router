# DVR 3.0 R7 — Public API closure

Status: **complete**

R7 replaces the package root's accidental mature-Core export graph with one explicit
plugin/compatibility contract and publishes a matching declaration surface.

## Before R7

The package root was:

```text
lib/public-entry.js
  -> export * from ../entry.js
entry.js
  -> export * from ./index.js
index.js
  -> mature Core + algorithm/helper exports
```

A runtime import of the built package exposed **122 names**. Most were implementation
details such as OCR helpers, pixel-diff utilities, cache primitives, HTTP/provider helpers,
SVG rendering helpers and routing internals.

Those names were public only because of transitive `export *`; they had no package-root
ownership contract.

Repository reachability review found no production or test consumer importing those Core
helpers through `dsh-vision-router` or through `entry.js`. Existing direct entry
consumers use the public Config/revision contract, while Core tests import `index.js`
or the owning module explicitly.

## Deliberate runtime surface

R7 removes `export * from './index.js'` from `entry.js`.

The package root now exposes exactly:

```text
Config
SETTINGS_CONTRACT_REVISION
apply
name
inject

sessionSurfaceReplacementIntent

ensureVisionAttachmentAdmissionPolicy
hasBatchAttachmentContract
hostOwnsOfficialDeepSeekProvider
installHostSettingsCompatibility
installVisionAttachmentAdmissionPolicy
protectHostProviderOwnership
```

Classification:

- **plugin contract**
  - `name`
  - `inject`
  - `Config`
  - `apply`
- **supported DVR contract**
  - `SETTINGS_CONTRACT_REVISION`
- **compatibility API**
  - `sessionSurfaceReplacementIntent`
  - the six explicit DSH compatibility helpers above
- **accidental internal**
  - every former transitive mature-Core/helper export
- **test-only**
  - none are published through the package root

The mature Core remains importable inside the repository from its owning source/artifact;
R7 does not delete or rename its internal exports.

## Type surface

R7 adds one hand-owned declaration:

```text
src/lib/public-entry.d.ts
  -> build
lib/public-entry.d.ts
```

It intentionally declares only the runtime faces above.

Dynamic Host values remain `unknown` at the package boundary instead of inventing a DVR
copy of the DSH Context graph. The Session replacement variants and the narrow
compatibility result/options that DVR actually owns are declared explicitly.

No internal typed owner is re-exported merely because it exists.

## Package resolution

The package follows the current DSH publication shape:

```json
{
  "main": "lib/public-entry.js",
  "types": "lib/public-entry.d.ts",
  "exports": {
    ".": {
      "types": "./lib/public-entry.d.ts",
      "default": "./lib/public-entry.js"
    }
  }
}
```

The existing `main` remains for runtime compatibility.

`./client` stays a DSH loader entry and is deliberately **not** promoted to an ordinary
typed consumer-library API.

## Source/artifact ownership

The R1 builder now understands canonical `.d.ts` source files:

- `.js` canonical source is copied as runtime JavaScript;
- `.ts` canonical source is compiled to JavaScript;
- `.d.ts` canonical source is copied as a declaration artifact.

Generated declarations remain outside Git source-of-truth just like generated runtime JS.

## Permanent gates

`tests/architecture-contract-baseline.test.js` now locks:

1. root `main`, `types` and conditional `exports["."]`;
2. absence of `export * from './index.js'` in the entry boundary;
3. the exact twelve runtime export names;
4. a deliberate declaration for every runtime export;
5. no relative internal-module re-export from the root declaration;
6. no DSH private `/src/` dependency in the public declaration.

This means a new Core export cannot silently become package API again.

## Validation

At R7 closure:

- canonical build: success;
- generated-artifact check: **182 artifacts in sync**;
- Host TypeScript program: success;
- Client TypeScript program: success;
- built root runtime export count: **12**;
- public API / Config / DSH compatibility targeted tests: **66/66**.

R7 therefore closes both halves of the package boundary: runtime names and TypeScript
names are deliberate, narrow and independently owned.
