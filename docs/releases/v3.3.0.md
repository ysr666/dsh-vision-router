# v3.3.0 — Native OCR route and resilient visual tools / 原生 OCR 路线与视觉工具稳定性

**Status / 状态:** Reviewed **minor-version release candidate**, **not published**. Only the protected Release workflow on the exact merged `main` SHA, an immutable tag, npm `latest` with matching tarball identity/provenance, and an official GitHub Release can establish publication. / 这是**待审核并待发布的次版本候选**，文档或 PR 通过不代表已发布。

## Why a minor version? / 为什么升为次版本？

This release includes a new owner-installed native OCR engine route and a substantial set of security, execution-lifecycle and Host compatibility improvements compared with the last published `v3.2.1`. The previously prepared `v3.2.2` metadata was **never released**; these changes are consolidated into `v3.3.0`, rather than shipping a patch version with an expanded native OCR capability. / 相比已发布的 v3.2.1，增加原生 OCR 路线和较大范围的稳定性／安全增强。未正式发布的 3.2.2 候选不单独上线，统一作为 3.3.0。

## Changes since v3.2.1 / 主要变更

- **PP-OCRv6 small / ncnn local CPU OCR (#853–#854, #836):** In `vision_ocr(auto)`, prefer a locally **owner-installed and SHA-verified** worker on **macOS ARM64** or **Windows x64**, if the pinned executable and five model assets are actually installed. Otherwise the existing Tesseract compatibility path remains available. Explicit `engine=tesseract` / `engine=vision` still overrides auto. Uncertain but nonempty ncnn text can now request an existing consent- and deadline-controlled vision review; under strict local-only or failed review, the local transcript is returned with uncertainty preserved. / 已安装并校验的本地 ncnn 优先；未安装时仍走兼容路线；显式引擎选择不变；低置信度核查严格受权限、熔断与共同超时限制。
- **Tesseract compatibility for subtitle text (#853):** Add PSM 7 single-line analysis and bounded grayscale, inversion/scale retry for hard light-on-dark captions, without presenting Tesseract as the primary native OCR target. / 兼容路径支持单行模式与适度反色、放大重试。
- **Attachment/Session safety and whole-task deadlines (#852, integrating #838–#846, #850–#851):** Unify `attachmentIds` and file paths through Session-authorized image processing, remove cross-Session cache bypasses, start the shared deadline before cold Host lookups, abort noncooperative operations on deadline, and propagate cancellation through provider attempts. Preserve privacy-safe phase diagnostics. / 统一附件读取、修复跨会话缓存授权风险、提前启动统一时限并正确传递取消信号，不泄露完整附件 ID。
- **Native VTracer containment (#852, incorporating #847–#848):** Move the native/WASM trace job into a bounded child process; accept SVG only after a clean child exit, and fail closed on abnormal exit, timeout, forged/oversized output. This changes process overhead, not the tool API. / VTracer 由受限子进程隔离，避免原生错误直接终止 Host；会有一定启动开销。
- **Windows reliability (#852, incorporating #845):** Address atomic cache rename and portable tarball identity/test behavior. / 修复 Windows 文件锁、缓存写入与打包回归测试问题。
- **Release gate repair (3.3.0):** Run the newly introduced native-OCR `node --test` suite as actual tests (not arguments to `license:check`); require both dependency and native-asset notice/license checks in the protected Release metadata gate. Add immutable tests to catch this divergence. / 恢复此前误漏跑的原生 OCR 回归入口，同时保持原生许可证检查不可绕过。

## Evidence and known limits / 验证与未覆盖边界

- #852 integrated head passed **15/15** GitHub Actions workflows; #853 and #854 each have independent CI evidence. Mac ARM64 real installed PP-OCRv6/ncnn `vision_ocr(auto)` recognized generated Chinese-caption PNG fixtures with both dark-on-light and light-on-dark text correctly. This does **not** represent the original Issue #836 reporter files; the exact reporter's images were not available.
- Earlier Windows x64 native-worker builds and real Host `vision_ocr(auto)` tests were documented, but a freshly installed Windows worker was not available in the later isolated acceptance session. Actual current 3.3.0 final CI and Release gates must pass; **do not describe this candidate as publicly released before then**.
- Some legacy Tesseract inputs still misread stylized captions; the engine remains a compatibility fallback, not the native first choice. The previous Issue #841 reporter's specific 120-second environment was not independently reproduced, despite correcting demonstrable deadline/cancellation weaknesses.
- **Native OCR redistribution is a separate gate:** The npm package includes JavaScript, installer, license texts and integrity metadata, but **does not bundle PP-OCRv6 model weights or native executables**. The lab audit `quality/native-ocr-license-audit-LAB.md` explicitly marks native archive redistribution as **not yet cleared** (clean CI, final notices/SBOM, hosting and platform verification pending). Do **not** attach lab worker/model archives to this GitHub Release or advertise an automatic public download until those gates pass. / npm 仅分发源码相关 JS、安装器和许可文本；原生可执行文件和模型不随 npm 发布，离线包尚未获公开分发放行。

## Compatibility and privacy / 兼容与隐私

- **DSH:** `>=0.2.1-rc.5 <0.3.0-0`. **Node.js:** `>=24.9.0`. The exact recommended reviewed Host is DSH `0.2.2-rc.1`; rc.2/rc.3 have separate exact-source acceptance evidence. Older rc.2/rc.3 *from the 0.2.1 line* are below the current floor and must not be forced into loading the plugin.
- **No automatic profile migration**, no change to Host-owned Session/attachment trust boundaries. Back up the DSH profile, Settings, attachments and important Session history; run read-only `doctor --upgrade-preflight`; keep a known-good `v3.2.1` rollback.
- **Privacy:** Fresh installs still enable an anonymous cloud vision fallback. Images and related request metadata may leave the machine unless strict local-only mode is enabled. Installing a verified native worker does **not** imply the entire vision chain is offline.
- Third-party generated Desktop installers are not independently qualified merely by the official Host gate. / 第三方打包安装器需要单独验收。

## Publication acceptance / 最终发布门禁

The reviewed 3.3.0 candidate must pass all CI checks (Node 24.9/24.21 and exact DSH Host matrix), frozen-lockfile install, source/runtime build verification, reproducible package, complete native OCR regression suite, native+VTracer license checks, publication channel `latest`, pre-tag npm registry identity check, immutable main-target tag, npm trusted publishing/provenance, and a post-release npm/GitHub package hash check. No partial pass or green former PR alone authorizes publication. / 最终版本必须以完整 CI、受保护发布流水线和 npm/GitHub 包体哈希一致为准。
