# v3.0.0

DSH Vision Router 3.0.0 is the ownership release. Vision authority now belongs to a
durable, explicitly owned Session policy instead of ambient session state; the
package root is a deliberate, typed public API instead of a monolithic
implementation file; and the runtime installation is grouped into explicit
composition phases with an explicitly passed provider transport. It also closes the
R10 correctness work, the R11 adversarial final audit, and hardens the release
pipeline itself.

## Highlights

- **Session Vision policy has a durable owner.** A scoped policy store, backed by
  the Host storage domain, owns Vision authority per Session: it hydrates before a
  child session publishes, carries into direct Vision checks, and binds delegation
  to the Host Agent lifecycle instead of re-deriving authority from ambient state. A
  scoped volatile backend keeps hosts without durable storage working.
- **Deliberate package root.** The monolithic `index.js` entry is replaced by a
  curated public entry with its own declaration file, and `exports["."]` now carries
  `types`. The packed public-API contract executes that entry, checks its lifecycle
  preconditions and arity, and type-checks a consumer sample against the shipped
  declarations.
- **Explicit composition and transport ownership.** Runtime installation is grouped
  into explicit phases; router-owned provider HTTP receives its
  `VisionProviderTransport` explicitly, and Core no longer installs a process-wide
  proxy fetch. Provider probes — live model discovery and the settings connection
  check — run inside the same configured-pair proxy scope as vision turns, taking the
  transport the proxy boundary owns rather than reading the process global at call
  time.
- **R11 adversarial final audit.** Twenty findings closed, each recorded together
  with the artifact that guards it, plus the mechanical gates that keep the defect
  classes from returning: source-ownership lint rules, the bundle-patch activation
  shim contract, the offline release state machine, and boundary tests against a real
  Host.
- **Release-pipeline integrity.** The release state machine is refusal-first and
  draft-safe; registry identity and package content are compared before and after
  publishing; the README announcement bars and the release notes are hard gates; the
  pnpm-free Windows runtime smoke now receives built artifacts instead of installing
  a package manager.

## Breaking change: a new required peer

3.0.0 adds one required peer dependency:

- `@deepseek-ai/dsh-storage-domain` `>=0.1.5-rc.1 <0.2.0-0 || >=0.2.0-rc.2 <0.3.0-0`

It backs the durable Session Vision policy layer. A Host that cannot provide the
storage domain cannot persist the policy and therefore must be upgraded first.
Existing Vision Router settings, profiles and historical Session data keep working:
the policy store is additive and hydrates from the Session when no durable entry
exists yet.

## Host support window

Unchanged from 2.3.x:

- DSH 0.1.x: `>=0.1.5-rc.1 <0.2.0-0`
- DSH 0.2.x: `>=0.2.0-rc.2 <0.3.0-0`
- ordinary development Host: exact `0.2.0-rc.2`

## Validation

- the full gate battery on the exact release commit: install, build, build:check,
  source-ownership lint, source→artifact evidence, reproducible clean build,
  typecheck, the test suite, client-source synchronization, the Host support-window
  contract, and the packed public-API contract;
- the real-Host compatibility matrix, adversarial compatibility/fuzz gates and the
  resource-stress gates;
- consumer verification of the installed package on both targets (a `dsh web`
  profile installed from the repository, and a real Desktop shell): a real image turn
  reaches the provider with the image and the configured credential attached, live
  model discovery reports the live models, and the Vision Router settings surface
  renders.

The audit and its evidence index are recorded in
`docs/architecture/3.0-r11-adversarial-review.md`.

## Upgrade

Users on 2.3.0 with a supported Host can upgrade in place; Vision Router settings and
existing Session data are read as before, and the durable policy store starts empty
and hydrates from the Session. On a Host that predates the storage domain, upgrade
DSH first. Remote Settings keeps its existing product contract: its confirmation is
an acknowledgement, not an authorization credential, and mutation stays bounded by
the explicit allow-list and local-only fields.
