# v3.0.1

DSH Vision Router 3.0.1 is a corrective release on the 3.0 line. It ships the five
consumer-visible fixes that were merged after v3.0.0 was tagged: two in the Desktop
settings surface and three in the provider egress paths, where a configured `proxy` /
`proxyHosts` must reach every leg that talks to a provider. There are no new peers, no
settings migration, no Session format change and no public API change.

## Highlights

- **Desktop settings values (#619).** A Host that exposes a legacy-shaped
  `settingsScope` can return an empty `vision-router` namespace while its native config
  forms keep working. That scope is now kept only as the delegate for every other
  namespace instead of bypassing the local settings bridge, so the Vision Router
  settings surface reads and writes real values on the Desktop shell.
- **Model picker catalog (#620).** The model-visibility boundary now patches every
  loader instance it can reach — including one published after the boundary installs —
  so the picker no longer groups the same model twice.
- **Background and local provider legs (#623).** The Router-owned provider transport is
  threaded into the local vision stabilizer, the host/security boundaries and the
  background benchmark, so those legs honor `proxy` / `proxyHosts` exactly like
  foreground vision turns.
- **Connection probe egress (#633).** The settings "test connection" probe now takes the
  Router-owned transport (`runtime.providerTransport`) instead of relying on the legacy
  configured-pair scope, which by construction cannot cover a `vision-http` direct
  backend — the plugin's default shape. The legacy boundary fetch stays as the fallback
  for Hosts that only configure the legacy scope.
- **LM Studio native transport (#634).** `callLocalBackend`'s `format: 'lmstudio'`
  branch no longer drops `providerTransport`, and the native `POST /api/v1/chat` goes
  through `transport.fetch`, matching the openai and anthropic legs. A remote LM Studio
  behind a proxy is reached like every other provider.
- **Internal hardening (no package behavior change).** Exact Node-runtime and Playwright
  system-package caches, Desktop adversary sharding and scenario concurrency, a Host
  contract gate that derives the settings seam from the Host it meets, an alpha canary
  that runs every contract instead of stopping at the first failure, and completed e2e
  workflow trigger coverage.

## Host support window

Unchanged from 3.0.0:

- DSH 0.1.x: `>=0.1.5-rc.1 <0.2.0-0`
- DSH 0.2.x: `>=0.2.0-rc.2 <0.3.0-0`
- ordinary development Host: exact `0.2.0-rc.2`

The 0.2.x train is admitted from the verified `0.2.0-rc.2` boundary. The `0.2.1` alpha
line is inside that admitted range and is exercised by the scheduled drift canaries,
which read the settings seam from the Host they install; the exact-evidence boundary is
still `0.2.0-rc.2`.

## Validation

- every fix carries a failing-first reproduction that fails on the pre-fix commit and
  passes on this release commit — the Desktop settings and picker boundaries, the local
  and background transport legs, the `vision-http` probe, and the LM Studio native
  transport;
- the full gate battery on the exact release commit: install, build, `build:check`,
  source-ownership lint, source→artifact evidence, reproducible clean build, typecheck,
  the test suite, client-source synchronization, the Host support-window contract, and
  the packed public-API contract;
- a real-Host pass on this exact build against an installed DSH checkout: the Host proxy
  egress contract, the settings lifecycle in a real browser (mount, save, reload and
  readback of the Vision Router section) and the Desktop Host injection contract
  (structured injections, token exchange, authenticated index and DVR RPC);
- the real-Host matrix (Windows Node 22/24 Desktop, macOS renderer, Linux real Host +
  Chromium), the adversarial compatibility/fuzz gates and the resource-stress gates;
- an adversarial review of this delta, including a provider-egress sweep over every
  server-side entry point. The one candidate that looked like a further bypass — Ollama
  cold start — is gated to loopback hosts and was recorded as falsified rather than
  patched.

## Upgrade

Drop-in replacement for 3.0.0: no settings migration, no Session format change and no
new peer dependency. Upgrading `dsh plugin --profile web add github:ysr666/dsh-vision-router`
(or the pinned `dsh-vision-router@3.0.1`) keeps existing Vision Router settings and
Session data readable as before.
