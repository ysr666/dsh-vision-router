# v2.2.5

DSH Vision Router 2.2.5 is a privacy and Desktop multi-plugin isolation update for the DSH 0.1.7 line.

## Highlights

- Adds **Local-only vision / 仅本地视觉**. When enabled from the local Settings page, Vision Router permits only loopback visual endpoints (`localhost`, `127.0.0.0/8`, `::1`) and fails closed against configured cloud/DSH vision providers and the built-in anonymous OVHcloud fallback. Saved cloud configuration is preserved, and disabling the policy restores the previous chain. This policy covers Vision Router visual egress only; a remote chat model can still receive the resulting text.
- Fixes the remaining `dsh-vision-router@2.2.4` Windows Desktop multi-plugin startup hang reported in #551. The local/auth route boundary no longer leaves a replacement `webServer.register` on Cordis's shared WebServer service for the DVR fiber lifetime. DVR now shadows only its own injected child-context WebServer view, so unrelated plugins keep the original registrar while DVR-owned routes retain the same Host-auth/local capability checks.
- Strengthens the exact DSH `0.1.7-rc.2` Windows Desktop gate: it now exercises launch-token → cookie authentication, authenticated index and `/api` requests, DVR RPC, Node 22/24, and six deterministic Node 24 multi-plugin load orders with a foreign WebServer registrar observer.
- Keeps the public minimum supported DSH Host at `0.1.0-rc.8`; no settings migration is required.

## Upgrade

Users on DSH `0.1.7-rc.2` Desktop, especially those who still see `Loading plugins…` with Vision Router 2.2.4 in multi-plugin profiles, should upgrade to 2.2.5. The reporter's original issue remains open until a post-release field retest confirms the fix on the affected machine.
