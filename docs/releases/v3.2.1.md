# v3.2.1 — Settings recovery, VTracer and RC2 Host qualification / 设置恢复、VTracer 与 RC2 兼容验收

**Status / 状态：** This is the curated stable v3.2.1 **release candidate note**. A successful protected Release workflow, GitHub Release, npm `latest` and matching package/provenance are necessary before it may be called published. / 本文是 v3.2.1 正式候选发布说明；实际发布必须以受保护 Release 工作流、GitHub Release、npm `latest` 和一致的包体及来源证明为准。

## Since v3.2.0 / 相对 v3.2.0 的变化

- **Settings bridge recovery (#823, #828):** Unify the opt-in local/authorized remote configuration path, eliminate conflicting compatibility-script ordering, and mount the native provider settings bridge through the correct Host lifecycle. Reinforce authentication, redaction, permission boundaries and Settings save/readback/reload regression coverage. / 统一本地及经授权的远程设置通道，修复兼容脚本加载顺序和原生设置服务挂载时序，补齐认证、脱敏、权限和设置保存／回读／重载验证。
- **SVG trace backend (#829):** Replace `potrace → jimp → @jimp/core` with pinned `@visioncortex/vtracer@1.0.0-alpha.4` WASM in an isolated Worker. Preserve the public `vision_trace` entry point while improving dependency/license provenance checks and image-quality test coverage. The trace renderer changes, so SVG path geometry and output may differ from v3.2.0. / 将 SVG 追踪依赖从 Potrace/Jimp 换为固定版本的 VTracer WASM Worker；保留公开工具入口，强化依赖许可与输出质量测试。生成的 SVG 路径形状可能与旧版不同。
- **Exact DSH 0.2.2-rc.2 acceptance (#830):** Pin official upstream source SHA and verify Session atomic-batch per-event semantics, route ownership, three-OS Host contracts, Chromium Settings and paste flows, macOS and Windows real Desktop, candidate tarball installation, and separately diagnose immutable published 3.2.0 on the real RC2 CLI/Web Host. / 固定 RC2 上游精确提交，对批量事件、路由、三端、真实浏览器／桌面、候选安装包及历史 npm 包做独立验收。
- **CI supply-chain maintenance (#824, #825):** Upgrade pinned CodeQL SARIF uploader and pnpm/action-setup; cover all 30 relevant workflows including the new RC2 gate. / 更新 CodeQL 与 pnpm Actions 固定 SHA，覆盖全部相关工作流。

## Compatibility and safe upgrade / 兼容边界与安全升级

- **No support-floor relaxation:** DSH `>=0.2.1-rc.5 <0.3.0-0` and Node.js `>=24.9.0` remain required. DSH `0.2.1-rc.3` and `0.2.0-rc.2` are **not** compatible with DVR 3.2.x; do not bypass the Host's engine admission checks. / 最低要求不变，较旧 DSH 版本明确不支持，不建议越过安装器的兼容检查。
- Run the read-only `doctor --upgrade-preflight`, back up your current DSH profile, Settings, attachments and important historical Session records, and preserve a known-good rollback path. DVR does not automatically rewrite or delete Host-owned history. / 升级前只读预检、备份、核验重要会话并保留回滚；插件不自动清理或改写 Host 数据。
- Official real Host/CLI/Web and macOS/Windows Desktop gates were run on supported exact source lines. **Third-party Dataelem Desktop's generation installer remains a separate path**: removing the Jimp chain addresses the identified dependency closure trigger but is **not evidence of a successful installation of the new npm release in that installer**. Its upstream issue and fix review remain independent. / 官方安装和第三方代际安装器须分开评价；移除 Jimp 是源码层解决已知依赖链，不代表第三方安装路径已获实测认证。
- No change to the default cloud-vision image egress: the anonymous fallback can transmit image content to a remote provider unless strict local-only mode is selected. / 默认云端视觉链仍可能将图片传给第三方；涉敏内容应启用严格纯本地配置。

Never infer publication merely from this document or a Git tag. / 最终提交须重新通过 CI 与受保护发布门禁，对 npm 与 GitHub 的同一包体、哈希和来源证明作交叉核验。
