# v3.0.5 release candidate

This is a corrective patch for the existing 3.0.x line, not an announcement that npm has already published it.

## Included
- #727: successful `vision_describe` guidance now uses a source-attributed `notice`, so a synthetic injected context does not terminate the assistant's visible answer. Original contribution from @kevindawn11-hash in #728 (authored commit `14c67c7`, preserved in history by merge #733), paired with Session V3/V4 source-boundary fix #731. The final merged source is `main@0fc51c3` and no npm publication is implied.
- #730: updated latest-alpha CI to accept DSH JSONL namespace plugin exports in addition to older defaults; the exact published alpha lifecycle passed on Node 22/24. This is CI-only.
- #721 qualifies DSH 0.2.1-rc.1 at upstream 1600d8a1e140dcde43a1a0941940a0480712c011 with exact source and real Host/Chromium/Settings/attachment CI.
- #722 fixes #719 by removing two unused imports of optional DSH dependencies, originally contributed by @m4ku1337 in #720. Missing optional peers must not prevent Desktop activation.
- #723 checks the actual OVHcloud VLM JSON body against its documented 10 MB limit before egress. Only the official OVH endpoint is affected; image content is not silently changed.

- #735: keep the Vision toggle clickable across a transient Host model-catalog refresh only when a valid complete source/wrapper pair remains; Host selection authority and all cold/unavailable/selecting gates remain unchanged. This mitigates the independently evidenced native-disabled click-loss case, but does not resolve the separate Host RPC fault tracked in #738.
- #737: add a privacy-bounded, test-only `gateway/internal` origin classifier for real Desktop evidence. It does not change runtime behavior or repair the intermittent Host failure.
- #736: improve English/Chinese onboarding and preserve visible cloud-data disclosure; no runtime or dependency changes.

## Compatibility
Node ^22.19.0 or 24+. DSH >=0.1.5-rc.1 <0.2.0-0 or >=0.2.0-rc.2 <0.3.0-0. No settings or session migration, new Host privileges, or API breaking changes.

## Qualification
Each fixing PR passed its final-head CI. #735 passed 98 checks (one conditional skip); #737 passed 33 checks (one conditional skip) plus manually dispatched DSH Alpha / 0.1.7 / 0.2.0-rc.2 exact Host gates (6/6, 5/5, 7/7). These were source and Host qualification tests, **not a clean install or an npm release of the final v3.0.5 tarball**. The candidate version still requires its own Node, packed artifact, real Host and browser verification. For detailed acceptance evidence see docs/development/v305-real-scenario-acceptance.md.

## Still open

- #716 (open): user-reported backend HTTP 400; four small synthetic OVH requests have since returned 200 from the maintainer's machine, but this does not explain the reporter's failures.
- #726 (open, low priority): TUI-only overlay not-found diagnostic noise; no speculative profile-composition change is included.
- #684 (closed): catalog-refreshed native click suppression received the bounded #735 mitigation. Its separate Host error class is tracked as #738.
- #704 (closed / awaiting reproducible evidence): historical billion-context coexistence report; no verified co-installation failure is claimed repaired here.
- #729 (still a PR): Atlas Cloud preset remains outside this release until the specific models' image-content behavior is verified.
- #703 (closed): upstream installer writer-lock contention was out of scope, not repaired by DVR.

Publication is a separate release gate and is not performed by this preparation PR.
