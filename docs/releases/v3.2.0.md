# v3.2.0 — Host and Node compatibility retirement / Host 与 Node 兼容窗口调整

This is the curated **stable** v3.2.0 release note. Actual publication is established only by the successful protected Release workflow, the immutable GitHub Release and the matching npm `latest` artifact; a source branch or tag alone is not a publication. / 本文是 3.2.0 正式版发布说明，是否发布成功须以受保护 Release 流水线、GitHub Release 和 npm `latest` 同一构建产物核验为准。

## Compatibility / 兼容性

- Minimum DSH `>=0.2.1-rc.5 <0.3.0-0` and Node.js `>=24.9.0`. Validated exact Host sources include DSH 0.2.1-rc.5 and 0.2.2-rc.1. Supported version-range admission is **not** a claim that every future DSH build has been tested.
- DSH 0.1.x, 0.2.0, earlier 0.2.1 RCs and Node 22 are no longer supported **by DVR 3.2**. Existing DVR 3.1.5 users can remain on their current working version while preparing the Host migration.
- DSH retains ownership of Connection authorization, API and trustedHosts. DVR removes its private readiness bridge and retains only a minimal `webStartup`/`webServer` injection-order patch required for independent third-party RPC routes; fully removing that ordering patch produced a reproducible Windows HTTP 405.
- One optional DSH LLM peer remains to prevent installation under old DSH 0.2.0-rc.2, which ignores `engines.dsh`. Strict pnpm dependency checks passed for both pinned supported Host lines.

## Stability and release security / 稳定性与发布安全

- Includes visual-provider timeout and cancellation safeguards, proper fallback and model routing, progressive vision deep-tool activation, bounded grounding checks, and Windows/macOS/Linux real Host / Desktop regressions.
- Release verification tests, reproducible build, exact-source cross-platform Host gates, CodeQL and HOL security passed on the candidate main commit, subject to fresh checks on the final release-only metadata commit.
- The preceding v3.2.0-rc.0 publication **failed before npm**: the OIDC-only publish job had no `node_modules` while `scripts/release-channel.mjs` imported `semver`. PR #813 made the CLI dependency-free; PR #817 closed macOS/Windows path-alias silent-success risks. The preexisting `v3.2.0-rc.0` tag stays immutable and is not republished.
- Stable v3.2.0 must use the protected `Release` workflow with `tag=v3.2.0` and an exact, fully checked `main` SHA. The workflow maps stable versions to npm `latest`, verifies the tarball against the pre-tag candidate, signs/checks provenance, then publishes the GitHub Release with matching assets. Never publish manually to bypass these gates.

## Upgrading an existing installation / 已有安装升级

1. Confirm Node >=24.9.0 and the actual DSH Host version meets the new floor. Prefer an exact-tested Host; do not assume untested 0.2.x releases have equivalent behavior.
2. Run the **read-only** `doctor --upgrade-preflight` before upgrading. It rejects known legacy Connection overlays, private readiness bridges, floating GitHub-version references and older Node; a pass does **not** guarantee complete historical data compatibility.
3. Back up profile, Settings, image/attachment state and historical Session records; separately read-validate the copied records with the **target** DSH Host before changing a working profile. User-owned custom patches require manual review. Do not edit or normalize the live Session event log.
4. Keep the prior known-good DVR 3.1.5 / Host environment available for rollback if real startup, Vision, Desktop reload, or data restoration fails. No automatic profile or Session migration/deletion is performed by this release.

## Known boundaries / 已知边界

- Older DSH persistence formats, including released v0 `permission/preset.origin` and older `subagent/descriptor` records, can fail in particular Host readers. This is an upstream Host migration issue, not a DVR-owned session rewrite. Do not promise a universally lossless upgrade.
- The separate upstream DSH stale-Fiber/HMR defect remains open; the DVR-specific reload/404 trigger is mitigated, not the entire Host lifecycle issue. The original reported Windows raw JS/CSS screenshot and certain user-field failures have not been conclusively attributed to DVR.
- Non-loopback network, reverse proxy, untested custom profiles and future DSH releases are not universally certified by loopback CI. The default cloud Vision fallback sends image content to remote providers unless strictly local-only is configured.

## 发布说明摘要（中文）

- **支持范围**：DSH >=0.2.1-rc.5、Node >=24.9；3.2 不再支持旧 DSH、Node 22，原先正常工作的 3.1.5 可暂不升级。
- **核心调整**：Connection 权限归还 DSH，保留保障其他插件 RPC 的必要顺序补丁，延续视觉链稳定性、深度工具和跨平台回归保护。
- **升级原则**：先运行只读升级预检、备份旧配置与会话、针对目标 Host 单独验收、保留回滚；不自动改写历史数据。
- **上游已知问题**：历史 Session 读取、HMR/Fiber 等不宣称已由本插件全部修复。
- **发布校验**：直接走修复后的受保护稳定版 Release 工作流，检查 npm `latest`、GitHub Release、包哈希及来源证明的一致性。
