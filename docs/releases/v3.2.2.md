## Changes since v3.2.1 / 相对 v3.2.1 的变化

- **Attachment-ID and cold Session recovery (#839–#844, #846, #850–#852):** The full vision task's deadline starts before the Host's cold attachment log lookup, image reads, normalization, and backend capability preflight. Pending Host promises are raced against cancellation, and Host/user abort is passed into backend attempts instead of being mistaken for provider failure. Session-derived attachment authority is checked against the owning Session, with cleanup and privacy-safe stage diagnostics. / 识图总时限从附件恢复前开始计时，覆盖会话日志查询、图像处理及后端预检；即使旧 Host Promise 不响应取消，工具也能按预算退出。取消信号继续传到模型请求，跨 Session 不得借用附件权限，诊断日志不输出原始附件 ID。
- **Cache authority hardening (#838):** Strengthen attachment/cache access boundaries and regression coverage so a prior content hash or cached answer cannot authorize another Session's attachment. / 加固缓存及附件权限边界，缓存命中不得替代当前会话的有效授权。
- **Native VTracer fault containment (#847–#848):** Successful WASM workers exit naturally rather than being terminated immediately after posting a message. A bounded child process (3 active, up to 8 queued) isolates remaining native process faults; abort, abnormal exit, forged or oversized SVG results fail closed. The public vision_trace tool remains. The pinned VTracer engine does not change; isolated-process startup adds latency (about 90–100 ms per trace in a small macOS benchmark) and should be considered by performance-sensitive users. / 成功的 Worker 自然退出；原生计算由限流子进程承载，异常退出、取消或不合规 SVG 不会直接破坏主 Host。公开工具不变，新增进程启动开销。
- **Windows reliability (#845):** Repair Windows-specific package/cache handling and associated image-input verdict checks. / 修复 Windows 打包、缓存和图片输入判断相关兼容问题。

**Issue #841 scope:** A genuine source-level deadline/cancellation weakness was fixed, but the reporting user's precise Windows ~120-second stall was **not independently reproduced**. A slow but responsive remote vision model can still legitimately use the configured task budget (default 120 seconds). Do not claim that all possible 120-second backend stalls are eliminated. / 已修复确定存在的超时与取消缺陷，但未独立复现报告者现场；默认 120 秒预算内的慢模型调用仍可能耗时，不能宣传为彻底消除所有长等待。

## Compatibility and safe upgrade / 兼容与安全升级

- Keep DSH **>=0.2.1-rc.5 <0.3.0-0**, Node.js **>=24.9.0**, and existing Host-owned Session/attachment/Settings authority. No support-floor relaxation or automatic profile migration. / 最低版本与 Host 权限归属不变，不自动升级或迁移 Profile。
- Before upgrading, back up the DSH profile, relevant attachments and important Session history; run the read-only `doctor --upgrade-preflight`; preserve the v3.2.1 rollback option. / 升级前备份重要资料并只读预检，保留回退到 3.2.1 的办法。
- Cloud visual inference still sends image content to the selected remote provider unless strict local-only mode is enabled. "Free/no key" does not mean offline. / 云端识图仍会将图像送往供应商；免 Key 不等于离线。
- Third-party generated Desktop installers remain outside the official cross-platform acceptance evidence. / 第三方代际安装器不包含在官方验收结论中。
