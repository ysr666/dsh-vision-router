# v3.0.2

DSH Vision Router 3.0.2 is a hardening release on the 3.0 line. It ships the fixes from a
full-repository adversarial review plus the follow-up pass over that work, the composer Vision
control's responsive-design fix (issue #654) and the presented-image delivery fix, together with
the one consumer-visible transport fix merged after v3.0.1 was tagged. There are no new peers, no
settings migration, no Session format change and no public API change.

## Highlights

- **The composer Vision chip follows the shipped chip and adapts to narrow rows (#654).** It used
  to draw its own 1px border, 12px type and a brand-coloured outline/fill while selected, and it
  kept its label at every width, so on a narrow composer it took more room and read heavier than
  its shipped neighbours. Its size, radius, hover, focus ring and selected state now come from the
  shipped chip tokens (the same ones `ui-plan`'s PlanChip and the access-mode trigger use) and it
  follows the composer row's size container: below the same 460px cut that chip uses, only the
  14px glyph remains. Measured in one window: 72px → 30px, label hidden, glyph kept.
- **The collapsed chip keeps the Vision eye; the check appears only while the label is there.** A
  bare check says nothing about what the chip does, and on a narrow row it is the only thing left
  on screen. The 14px slot now carries both glyphs and the same container query that collapses the
  label swaps them: the enabled chip shows the check at `@container (min-width: 460.01px)`, and the
  eye stays below that cut. Both states use the same fixed 14px slot, so the chip width never
  changes with the state. The guide copy no longer teaches the check as the on-signal.
- **A presented image lands in the message body, not only in a tool card.** The card shows a 240px
  thumbnail and every later message pushes it up (measured on a real host: the same image drifted
  from inside the viewport to 1692px above it within minutes). `vision_present` now also returns a
  paste-ready `replyImage` that the visible reply carries, and the host renders an absolute image
  path inside a message at full size through its own `api/file` route (measured in the DOM at
  640×200 for the same image the card showed as a thumbnail). The tool card stays, and it now
  centres itself when it mounts below the viewport — never when it is already visible, and never
  for history above the reader.
- **Instant local describe keeps the Router transport (#647, issue #646).** The instant local
  describe path now hands the Router-owned `providerTransport` to its adapter call, so a configured
  `proxy` / `proxyHosts` covers it exactly like every other provider leg.
- **Credential redaction is one shared list (#653, #655).** The log sink and the benchmark-failure
  diagnostic used to carry partial copies of the credential shapes, and each leaked what the other
  covered. One shared list now covers `Authorization` with any scheme (including
  `Proxy-Authorization`), `Cookie` / `Set-Cookie`, URL userinfo, `Bearer`, vendor keys (`sk-`,
  `ghp_` / `github_pat_`, `AKIA` / `ASIA`, `xox…`, `AIza…`), JWTs, PEM blocks and `key=value`
  assignments (including `#token=` fragments). A value that contains `;` is redacted whole, and a
  PEM block truncated before its END marker is redacted to the end of the text.
- **Adapter ownership no longer accepts a primitive marker (#653).** Three modules used to read the
  shared ownership symbol on their own, and two of them treated "the marker is not undefined" as
  ownership. Ownership now means "an object marker is present", so a foreign adapter that writes
  `'anything'`, `false`, `null` or `0` onto the symbol is no longer mistaken for the Router's own
  adapter; delegation, Session Vision authority and the tool boundary all read the same rule.
- **Proxy host admission normalizes what it compares (#653, #655).** A bracketed IPv6 literal and
  its bare spelling canonicalize to one host, and a `*.host` entry now matches the host it names
  plus its subdomains instead of silently matching nothing.
- **The background stop cache can neither go stale nor vanish (#653, #655).** A load that drops a
  record (expired, malformed or superseded) rewrites the file instead of leaving a stale row
  behind, and a failed cleanup write no longer discards the records that were read.
- **Failure classification and numeric settings resolve own keys only (#653).** Error codes and
  settings field names no longer resolve inherited values such as `constructor` or `__proto__`, and
  a hostile `message` / `toString` / `code` / `status` accessor can no longer make the classifier
  throw.
- **The retained-image walker is depth-bounded (#653).** It now shares the bound `convertBlocks`
  already applies to the same block tree, so a pathological message tree returns `false` instead of
  overflowing the stack.
- **Same-class hardening from the same review (#653).** Session Vision policy rows with
  prototype-carried fields are treated as malformed; an explicit `null` options bag means "no
  options" at four entry points instead of throwing from a parameter destructure; host capability
  evidence is tri-state, so only an explicit `true` proves the support floor; the doctor host probe
  is bounded even when the fetch ignores `AbortSignal`, and the error text it stores is redacted.

## Host support window

Unchanged from 3.0.1:

- DSH 0.1.x: `>=0.1.5-rc.1 <0.2.0-0`
- DSH 0.2.x: `>=0.2.0-rc.2 <0.3.0-0`
- ordinary development Host: exact `0.2.0-rc.2`

The 0.2.1 alpha line stays inside the admitted 0.2.x range and is now covered by a dedicated
adaptation note (`docs/architecture/dsh-021-alpha1-adaptation.md`) in addition to the scheduled
drift canaries.

## Validation

- every finding carries a failing-first reproduction that fails on the pre-fix commit and passes on
  this release commit, and the four residual items found by the follow-up pass were reproduced
  against the merged code before they were fixed;
- the full gate battery on the exact release commit: install, build, `build:check`, source-ownership
  lint, source→artifact evidence, reproducible clean build, typecheck, the test suite, client-source
  synchronization, the Host support-window contract and the packed public-API contract;
- a real-Host pass on this exact build against an installed DSH checkout: the Host proxy egress
  contract, the settings lifecycle in a real browser (mount, save, reload and readback), the Desktop
  Host injection contract (structured injections, token exchange, authenticated index and DVR RPC)
  and the macOS Desktop renderer lifecycle with a functional vision turn;
- counter-probes independent of the test suite: the eight review points go from 7/8 to 8/8 and the
  pre/post differential from 2/4 to 4/4, with the host-admission differential showing no widening
  for non-wildcard lists;
- the real-Host matrix on the release pull request (Windows Node 22/24 Desktop, macOS renderer,
  Linux real Host + Chromium), the adversarial compatibility/fuzz gates and the resource-stress
  gates;
- a write-scoped CI pass: the accepted risk posture is recorded in
  `docs/architecture/ci-risk-posture.md` and each workflow grant is narrowed to the job that needs
  it.

## Upgrade

Drop-in replacement for 3.0.1: no settings migration, no Session format change and no new peer
dependency. Upgrading `dsh plugin --profile web add github:ysr666/dsh-vision-router` (or the pinned
`dsh-vision-router@3.0.2`) keeps existing Vision Router settings and Session data readable as
before.
