# v3.1.4 — Stability and cross-plugin compatibility / 稳定性与跨插件兼容补丁

**Candidate release notes / 候选发布说明。** This document describes the code changes proposed for the v3.1.4 patch; publication is complete only when the protected release workflow verifies the exact `main` SHA, immutable tag, npm registry tarball identity, OIDC provenance and GitHub Release attachments. / 本文为待发布版本的源码变更说明；须经受保护发布流程核验精确主分支 SHA、不可变标签、npm 包体、OIDC 来源证明与 GitHub Release 附件，才能视为完成正式发布。

## Fixes / 已修复问题

- **#793 — Cross-plugin script ownership / 跨插件脚本隔离：** The index-injection hardening step now only rewrites DVR-owned scripts. It no longer edits unrelated client scripts from other plugins. A real pre-fix foreign-script mutation was reproduced and covered by tests. / 注入脚本加固只改写 DVR 自有脚本，避免误改写其他插件 JavaScript。已复现旧版缺陷，并加入回归测试。
- **#794 — Image fallback correctness / 识图回退正确性：** An image model yielding HTTP success but an empty answer no longer ends the chain and caches a misleading successful placeholder. The next eligible model may be tried under the same shared budget. Both tool-only and opt-in whole-turn routing are covered; failed-model partial text is not allowed to contaminate later candidates. / 视觉模型成功返回空内容时，不再提前终止和缓存伪成功，允许在原预算内继续尝试后端；覆盖默认工具识图与可选整轮路由，并隔离失败候选输出。
- **#794 — Bounded whole-turn execution / 整轮识图时限：** An image-bearing turn now has a bounded preflight and streaming execution even when a third-party adapter does not cooperate with abort or never settles its async iterator. Explicit Host/user cancellation remains distinguished. / 视觉整轮的模型预检查与流式等待均纳入总时限，即使第三方适配器不响应取消或流迭代不返回，也不会无限挂起；保留明确的用户/Host 取消行为。

## Non-runtime safeguards / 非运行时防护

- **#795 — Desktop renderer gate / Desktop 启动渲染门禁：** Real Desktop E2E now catches bootstrap JS/CSS unintentionally becoming visible document text, including through exposed head/script/style elements, and checks injection markup delimiters. This is **not** a proven fix of issue #792. / 真实 Desktop E2E 检测启动 JS/CSS 意外外露与注入标签边界；**不是** #792 的已确认根因修复。
- **#790 — Latest-canary maintenance / 上游 canary 维护：** Keeps DSH latest-canary and Settings seam drift checks aligned. No production runtime behavior changed. / 维护上游 canary 及 Settings 接缝漂移检测，不修改正式运行时。

## Acceptance / 验收边界

- Underlying fixes were reviewed with Node 22/24 and exact-source DSH Host/real Desktop gates. The **v3.1.4 release commit** must separately complete its own CI/security/Host tests and the protected publication workflow before it may be called published. / 源码修复已针对 Node 22/24 与真实 DSH Host/Desktop 门禁验收；**v3.1.4 发布提交**仍需独立通过 CI、安全、Host 测试及受保护发布流程。
- No change to default tool-only routing, user Settings schemas, Node/DSH support range, public API, runtime providers, remote privilege policy, or default cloud image-egress/privacy policy. / 默认工具识图、设置结构、Node/DSH 支持范围、公共 API、运行时模型提供商、远程权限与默认云端图片外发策略均未改变。
- **Still open:** #791's original 550/503 provider/HTTP source remains unverified. #792's startup raw-source window and possible multi-plugin conflict are not assigned a proven root cause; the regression gate does not certify a field resolution. / **仍在追踪：** #791 用户现场 550/503 来源不明；#792 启动窗口源码外露及可能的多插件冲突尚未确认根因，不宣称已经解决。

## Upgrade / 升级

After the trusted release is verified on npm/GitHub, update the DVR plugin to `dsh-vision-router@3.1.4` using the existing profile's normal plugin manager or explicit-version install, then restart/reload DSH as appropriate. Back up existing profile configuration before changing the plugin set; never delete conversation history to troubleshoot. / 正式发布确认后，按现有 profile 的插件管理方式升级到 `dsh-vision-router@3.1.4` 并根据环境重载；排错前备份配置，不要求删除聊天记录。
